HOW TO USE THE DATA QUALITY APPLICATION

Start: sign in, then click "New analysis" (or press N). Drop one or more CSV files (one table per file). Optionally give a domain, a business goal and what one row represents (a customer, an account, an operation): the analysis uses them, and a repeated identifier is normal when a row is not the thing the identifier names. The analysis runs in the background (validation, profiling, metrics, language-model insights); each table appears as soon as its metrics are ready. A version ends COMPLETED, PARTIAL (at least one table failed, the reason is shown) or FAILED; the Retry button runs it again. Uploading the same files again offers to open the existing version instead of creating a new one.

Tabs of a version (keys 1 to 9 switch tabs):
1. Overview: run status, quality score and grade A to D, the four dimensions (completeness, uniqueness, validity, consistency) each with the numerator and denominator it is computed from, or "not measured" with the reason; health of each table; columns to review.
2. Tables: profile of one table: columns, their role (identifier, reference, email, date, amount...) and why, frequent values, missing values, insights.
3. Data model: diagram of the tables and the relationships found from overlapping values.
4. Insights: semantic analysis: column roles, data contract, monitoring, causes and impacts. If the language model's answer fails validation, only figures measured on the data are shown.
5. Compare: differences with an older version: score, rows, columns added or removed, type changes, missing values.
6. Rules: quality rules and their result for this version. Types: no missing values in a column, at most X percent missing, unique values, at least N rows, at most X percent duplicates, minimum score, maximum drop in row count versus the previous version, values in the right format (email, phone, URL, date, number), order of two dates. A rule is WARNING or CRITICAL, can be paused, and is evaluated at the end of each run and on demand with "Check now". Rules proposed from the business goal or from the data are SUGGESTED (not verified) until you approve them; you can also dismiss them.
7. Corrections: fix what the application finds (extra spaces, N/A markers, dates in several formats, one value written several ways, duplicates), or write what you want in plain language (for example "write every country as France"). A preview shows how many values change, examples and warnings; an ambiguous date such as 01/02/2024 is never guessed. Applying creates a NEW version (analysed like an upload) with a log of what changed; the original version is never modified.
8. Graph: shows how the rows would become a graph (nodes, their properties, relationships), the conflicts found (one key with several different values, kept as candidates and marked, never silently chosen), and builds it in Neo4j. A file with no identifier column can still be linked when another table names its rows by line number; rows told apart only by a combination of references (an order and a line number) are identified by that combination; a column holding identifiers of the same table (a manager) links two rows of that table; NULL, N/A and similar markers count as no value; a table that only holds two references becomes a relationship. Findings say when a table is tied to nothing or a link is uncertain. Neo4j must be running; Neo4j Browser is at http://localhost:7474.
9. Ask: ask a question in plain language. Questions about the data itself (counts, who, which entities, relationships) are answered from the graph, which must have been built in the Graph tab; the query that was run and its rows are shown. Questions about quality (rules, why a rule fails, scores, missing values, findings) and about how to use the application are answered without the graph.

Report button: a printable page of the version (print or save as PDF, or download Markdown) with the definition of every score.
Shortcuts: Ctrl+K or / opens search and actions, N starts a new analysis.
Deleting a dataset removes its files and its graphs; it is refused while a run is in progress.

DEFINITIONS (as the application computes them)
- Completeness: filled cells out of all cells (rows times columns), over all analysed tables.
- Uniqueness: rows that are not an exact copy of another row, out of all rows. A repeated identifier is NOT a duplicate row.
- Validity: values that follow the format of their column (email, phone, URL, date), out of the filled values of the columns that have such a format. "Not measured" when no column was recognised as having a format.
- Consistency: rows where the approved date-order rules hold, out of the rows where both dates are filled. "Not measured" when no date-order rule is approved.
- Each dimension is shown as a percentage with its numerator and denominator ("141295 of 141295"), so the figure can be checked.
- Quality score of a table: 100 minus its average missing-value percentage across columns minus its duplicate-row percentage. The score of a version is the average of the table scores weighted by row count. Grades: A is 90 and above (Healthy), B is 75 to 90 (Good, minor gaps), C is 60 to 75 (Needs attention), D is below 60 (Poor quality).
- Rule severity: WARNING and CRITICAL are the importance given to a rule. A failed rule of either severity is counted as failed and raises an alert (live notice, a badge in the dataset list and a banner in the Overview); CRITICAL failures are counted and shown separately and in red, so they are the ones to fix first. Severity does not change how the rule is evaluated.
- Rule status of a result: PASS (the rule holds), FAIL (it does not, with the measured figure and examples), SKIPPED (it could not be evaluated, for example the column or table is missing).
- Column roles (identifier, reference, name, email, date, amount, quantity, category, location, status...) are guessed from the column name, its values and their formats; only the ones left unclear are decided by the language model. An identifier is expected to be unique; a reference repeats and points at something else.
